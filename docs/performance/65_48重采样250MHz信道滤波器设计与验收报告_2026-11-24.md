### 1.4 命令与矩阵

通用模板（严格串行，一次一个进程，`env -u LD_LIBRARY_PATH` 固定）：

```sh
env -u LD_LIBRARY_PATH build/dev-avx2/apps/openuwb_rx \
  --replay testdata/<dir>/raw_2s.sc16 \
  --channel 0 --interference off --period-ms 5 --summary 1000 --print packets \
  --taps <eq16|realtime|eq32|quality|ch250_eq16|ch250_eq24|ch250_eq32|ch250_eq48> \
  [--post-guard 83000 --sic preamble --sic-backend ipatov --sic-code 9 \
   --sic-reps 256 --sic-sfd 4z2]
```

- 5 个 SIC 场景（jam/near*）一律使用与既有回放日志一致的
  `--post-guard 83000 --sic preamble --sic-backend ipatov --sic-code 9 --sic-reps 256 --sic-sfd 4z2`；
  clean/try2 不带 SIC。
- **对称 ABBA 顺序**：每组的档位序列为 `A B C D E E D C B A`（try2 为 8 档 `A…H H…A`），
  同一档位的两轮分别位于正序前半与反序后半，可把机器漂移夹在中间。try2 共 16 次、回归共 50 次，
  合计 **66 次回放**；另补 6 次旧档对照（§5.3）。
- `completed` 的构成受盲捕窗口影响（例如 ch250_eq48 每轮 2237 个窗口），因此本文不把
  `fcs_ok / completed` 作为跨档 FCS 率；需要比例时同时给出绝对值和目标时隙口径。

## 2. 四档滤波器设计与实测频响

### 2.1 设计方法

- 原型采样率 `fs_proto = 65 × 737.28 = 47,923.2 MHz`；3 频带 Don't-Care Parks-McClellan
  （`scipy.signal.remez`）：通带 `[0, 250] MHz` 增益 1；带外阻带 `[f_oob, 368.64] MHz` 增益 0；
  空隙 `(368.64, 487.28) MHz` 不约束、仅检查；抗镜像阻带 `[487.28, fs_proto/2]` 增益 0。
- 严格对称奇数阶线性相位 FIR（`T = 65 × Hpad − 1`），float32 量化后归一化到 `sum(h) = 65`；
  对称误差 0，`upfirdn` 自检 `max|diff| ≈ 1.4–1.8e-15`。
- 指标均在 **float32 量化后、相对通带增益** 测量。设计脚本：
  `tools/dsp/design_resampler_65_48_ch250.py`；产物摘要：`testdata/resampler_65_48/design_ch250.json`。

关键物理解读：

1. **eq16 的 339 MHz 过渡带**：`f_oob=339` 意味着 276–322 MHz 突发几乎原样通过通带边缘——
   276 MHz 仅 **−1.69 dB**、300 MHz −6.28 dB，320 MHz 才 −14.4 dB。它救回 6 个包靠的是
   300 MHz 以上开始衰减，而不是真正“滤掉”整个突发；这也是其 OOB 指标只到 −35 dB 的原因。
2. **eq48 的 +24.8 dB 空隙过冲**：空隙位于 `(368.64, 487.28) MHz`，其中 431.0 MHz 出现
   **+24.78 dB** 峰。对 65/48 有理重采样，输入 300–322 MHz 的强突发经上采样后其镜像落在
   415–437 MHz，正好被该峰放大；因此 eq48 不仅没有抑制突发，反而在输出谱的镜像位置把它抬高，
   与 §3/§5 中 eq48 全面不进锁的实测一致。
3. **eq32 的 +4.37 dB 空隙峰** 量级小得多，但同样抬高镜像；其近距场景崩塌与旧 `eq32`
   （同 Hpad=32、无该峰）同档崩塌，说明 Hpad=32 档本身还有独立问题（§5.3），不能只归因于新系数。
4. **eq24** 空隙为 −6.22 dB（无过冲），276–322 RMS −11.71 dB，是四档中“抑制突发”与
   “不制造镜像峰”平衡最好的设计。

### 2.3 通带纹波与底噪影响（ENBW 估算，非 CIR 仿真）

以 first path = 0 dB 为归一化基准，假设输入为覆盖 737.28 MHz 输入 Nyquist（±368.64 MHz）的白噪声。
双边等效噪声带宽 `ENBW = ∫|H(f)|²df / |H(0)|²` 决定总底噪；理想 ±250 MHz 砖墙的 ENBW = 500 MHz：

| 档位 | ENBW | 相对不滤波（737.28 MHz） | 相对理想 ±250 MHz 砖墙 |
|---|---:|---:|---:|
| realtime（旧） | 704.5 MHz | −0.20 dB | +1.49 dB |
| eq16（旧） | 668.5 MHz | −0.42 dB | +1.26 dB |
| ch250_eq16 | 582.4 MHz | −1.03 dB | +0.66 dB |
| **ch250_eq24** | **549.6 MHz** | **−1.28 dB** | **+0.41 dB** |
| ch250_eq32 | 724.4 MHz | −0.08 dB | +1.61 dB |
| ch250_eq48 | 15541.9 MHz | **+13.24 dB** | **+14.93 dB** |

- **0.194 dB 纹波不是底噪问题**：它只是带内幅度随频率的平滑起伏（eq24 最大在 64 MHz、最小在
  218 MHz），带内积分增益为 −0.09 dB，不会抬高带内噪声；匹配滤波失配损失约 0.001 dB 量级。
  若 first path 恰在纹波最小点，相对 0 dB 基准最多再差 0.194 dB。
- **eq24 的总底噪比 realtime 低约 1.1 dB**（−1.28 vs −0.20 dB），因为 realtime 的过渡带到
  447 MHz 才结束，会放进 250–447 MHz 的噪声；eq24 在 309 MHz 后已压到约 −39 dB。
- **eq32/eq48 的底噪问题来自空隙过冲**：eq32 的 +4.37 dB 峰把 ENBW 抬到 724 MHz，比 eq24 高约
  1.2 dB；eq48 的 +24.78 dB 峰把 ENBW 抬到 15.5 GHz，相对不滤波升高 +13.2 dB，与回放中
  clean/try2/jam 全部 0 FCS 一致。
- 该估算假设白噪铺满输入 Nyquist。若模拟前端已把输入限带到 ±250 MHz，368–487 MHz 空隙没有噪声，
  各档 ENBW 会接近 500 MHz，差异基本消失，只剩 ≤0.2 dB 的纹波影响；若后续 CIR/匹配滤波只积分
  ±250 MHz，带外泄漏还会再被抑制，因此上表是偏保守的宽带口径。
- **Sensing/Radar 边界**：sensing 链默认使用独立的 `quality_minorder`（330 MHz 通带、0.005 dB 纹波），
  本轮未修改、未验证；在未做 CIR/距离旁瓣专项验收前，不应把 `ch250_*` 用于 sensing/radar。

### 3.2 读法与观察

- **`LOCK_STATS fcs_ok` 与 `path=target` 计数可差 1 帧**（同一目标时隙的重复候选/路径标记），
  因此表中同时保留 `目标 OK/时隙`（PACKET 路径口径）和 `LOCK fcs/exp`（锁统计口径），
  两者只在 ±1 帧内不一致，不影响结论。
- **分母差异**：`completed` 从 eq16 的 424–426 降到 ch250_eq16 的 409，是因为盲捕种子/候选窗
  数量变化，不是“少解了帧”。按 `FCS/completed` 会得到 92.0% → 97.3% 的假象；按绝对 FCS，
  ch250_eq16 比 eq16 **多 8–9 帧**，按目标时隙 397/398 vs 388/389 **多 8–9 个目标时隙**。
- **ch250_eq24** 目标时隙 398/398、绝对 399，是 8 档最高；`CIR_FAILED=1` 是锁定期的一次
  非目标候选窗，不影响目标时隙。
- **ch250_eq32** 虽能锁定，但目标时隙只有 384/394（SFD 失败 8、timing 失败 2；另有 1 个非目标
  CIR 失败），比旧 eq32（387/393）还低；其 `tmet/sfdmet` 中位数反而更小，说明失败不是“弱信号”，
  而是个别包被空隙/突变影响。

### 6.1 同进程微基准（`benchmark_sc16_burst_core --length 56000 --reps 50 --warmup 20`）

| (c) `ch250_eq24` | **仅实验，不升默认** | try2 最好（399、398/398、6/6），核耗时与 realtime 相同（+0.9%），空隙 −6.2 dB 干净；但在 jam/near348/near506 各 1/2 轮不进锁（3/10），出现 17–904 丢队列，clean 也 −4 帧。条件：先定位 SIC 场景锁获取边缘问题，并增加重复轮次确认。 |
| (d) `ch250_eq32` | **不推荐** | 空隙 +4.37 dB；try2 目标 384/394（比旧 eq32 还低）；clean 380/390；near348 30/45、near506 71/71、dropQ 600–1174。近距崩塌与旧 eq32 同档一致，说明该档本身不可靠。 |
| (e) `ch250_eq48` | **明确禁用** | 空隙 +24.78 dB；clean/try2/jam 全 0 FCS、0 目标时隙、2 千级窗口、566–1261 丢队列；只有近距 0.70 m 强信号可用。 |

### 8.2 使用建议（有条件）

1. **默认保持 `--taps eq16`**，直到完成上板、长时和多场景重复验证；本轮不改变默认行为。
2. 若现场确认存在 `[-322, -276] MHz` 宽带突发，建议**显式**使用 `--taps ch250_eq16`：
   它在本矩阵中同时满足“救回 6/6”和“全场景无回退”，代价最低（Hpad16，核耗时与 eq16 持平）。
   注意它的 `f_oob=339 MHz`，对 276–300 MHz 只有 −1.7～−6.3 dB，6/6 是该夹具突发能量
   集中在 300 MHz 以上/322–368 MHz 的经验结果；若现场突发下移到 276–300 MHz，应改用
   `ch250_eq24`（先解决其锁获取问题）或重新设计，不能直接外推。
3. `ch250_eq24` 可作为实验档位在干扰场景 A/B，但**不建议在 SIC 场景默认启用**；其
   try2 优势（399 vs 398）相对于 ch250_eq16 只有 1 帧，却引入 3/10 轮（补充复核后近距约
   2/4 轮）锁定风险，收益/风险不成比例。其总底噪比 realtime 低约 1.1 dB（§2.3），
   纹波不是主要问题；主要问题是间歇性不进锁。
4. `ch250_eq32/eq48` 不应进入默认候选；若要继续研究 Hpad32/48，应先解决近距/SIC 下的
   锁获取问题与空隙过冲，再谈增益。
5. **不要把 `ch250_*` 直接用于 sensing/radar 的 CIR 链**：该链默认 `quality_minorder`
   （330 MHz、0.005 dB 纹波），本轮未改也未做 CIR/距离旁瓣验收；ch250 的 250 MHz 通带与
   0.19 dB 纹波对 sensing 的影响需要独立评估。

## 9. 风险与未做验证

### 9.1 风险（按优先级）

1. **ch250_eq24 的间歇性不进锁（中高风险）**：3/10 回归轮在 SIC 场景 acquire 阶段崩塌，
   独立复核又见 near348 1/2、near506 1/2 崩塌（近距合计约 2/4），jam 2/2 通过；
   参数与正序轮逐字相同，锁定后目标时隙全 OK，说明不是解码质量问题。旧 realtime 同档稳定，
   因此不能归因于 Hpad=24 本身。建议专项复现（多轮、固定 CPU、记录 acquire 种子/首包），
   确认是否与 250 MHz 低通的群时延/瞬态或 SIC 模板有关。**在定位前不要把 eq24 设为默认。**
2. **ch250_eq48 的空隙过冲（高，已可判定）**：+24.78 dB 峰把 300–322 MHz 突发的镜像抬高，
   clean/try2/jam 全部 0 FCS。即使旧 quality 同档也不稳，该设计不应使用。
3. **ch250_eq32 的近距崩塌（中）**：与旧 eq32 同档一致，属于档位既有问题；但 +4.37 dB 空隙
   峰没有帮助，clean 还出现 −4～−14 帧。若必须用 Hpad32，需要单独排查。
4. **样本量**：每个场景仅 2 轮（ABBA 各 1 轮），FCS 差 1–2 帧不足以区分；eq24 的 3/10
   失败提示运行间方差不可忽略，后续应以 ≥6 轮/场景复核。
5. **时序噪声**：矩阵期间有短时同进程微基准，P95 长尾可能偏高；离散 FCS/槽位结果不受影响。
6. **`completed` 口径**：不同档位的盲捕窗口数差异很大（409 → 2237），任何 `FCS/completed`
   的跨档比较都会失真；本报告已统一以绝对 FCS + 目标时隙为准。

### 9.2 未做的验证（必须显式列出）

- **未上板**：全部为 `--replay` 文件回放，没有 X410 + DW3000 的实时/射频证据，
  不能据此声明现场链路可用。
- **未做 MATLAB 交叉验证**：`UWB_demodulation/` 的检测位置/CFO 没有与本次 C++ 输出逐样点对齐；
  滤波器频响只做了 `scipy.signal.upfirdn` 自检，未与 MATLAB 重采样逐样点比对。
- **未验证 65/32**：491.52 MSps 路径不在本轮范围；同样未验证 TWR/ToA、Radar/Sensing。
- **未做 AVX-512 运行验证**：本机 i7-12700 无 AVX-512，`native-avx512` 仅全量编译 + 符号核验。
- **未覆盖其他 HRP code/前导长度**：只测 code10/256-SYNC/4z2 的既有数据集；code9–12、
  64/16-SYNC 未测。
- **未做长时/热稳定/多 worker**：只跑 2 s、2 worker；4 worker、温度/降频、长时间运行未测。
- **未做旧二进制同参数 A/B**：旧档对照使用当前 `9f4029b` 二进制的旧 taps（realtime/eq32/quality），
  不是重建历史提交的二进制；因此只能说明“同二进制下旧 taps 的行为”，不能完全替代版本级回归。
- **未做 SIC 深度评估**：SIC 仅按既有参数使用，未评估新滤波器对 SIC 重构精度的影响；
  eq24 的间歇失败是否与 SIC 模板相关尚未证实。

## 附录 A：统计口径

- 完整帧 FCS：`PACKET status=OK && fcs=1`。
- `目标 OK/exp`：`LOCK_STATS fcs_ok / expected_slots`；`expected_slots` 在 reacquire 时按
  generation 重置，故 `acquire` 行显示 0/0，不能用其它 slot 冒充。
- `FCS 绝对`：所有 `path=acquire/target/candidate` 的完整帧总数；`completed` 是窗口数，
  两者不可混用。
- `tc>0`：`timing_coarse>0` 的 PACKET 行数；`sfdwin≤1`：`0<sfd_win<=1` 占 `sfd_win>0` 的比例。
- `tmet/sfdmet/cirmet`：全体 PACKET 该字段的 P50（失败帧可能为 0，故只作相对参考）。
- 百分比/P95：最近秩；两轮并排给出，不合并掩盖差异。
- 所有回放均 `--interference off --period-ms 5 --summary 1000 --print packets`；
  SIC 场景额外 `--post-guard 83000 --sic preamble --sic-backend ipatov --sic-code 9
  --sic-reps 256 --sic-sfd 4z2`。
