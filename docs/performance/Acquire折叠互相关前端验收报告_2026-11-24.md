## 1. 证据边界与口径

- 完整帧 FCS：`PACKET status=OK && fcs=1`；`FINAL fcs=X/Y` 的 Y 是 `completed`（候选窗口数），
  不是目标时隙数。`completed` 会被自相关候选窗/重试窗放大，因此**跨臂比较必须看 FCS 绝对值**，
  不能只看 `FCS%`。
- `FINAL acq_seeds` 与 `COST_TOTAL acq_seeds` 在本矩阵一致；xcorr 模式另有
  `xcorr_windows`（Stage-1 执行次数）/`xcorr_stage2`（进入 Stage-2 次数）/`xcorr_seeds`
  （当前前端实例累计，`AutocorrGate::reset` 会清零）。
- “首锁延迟”用**第一个 `status=OK` 的 `PACKET time_ms`** 作为“首个完整帧成功”代理指标；
  另列第一个 `path=target` 的 `time_ms` 与首个 `LOCK state=locked` 的行号/上下文。
  由于 2 worker 会并行回填，日志行号不严格等于包序，但 `time_ms` 最小者与首个 OK 行一致
  （已逐日志核对）。
- `acquire` 阶段失败：统计 `PACKET` 行中 `path=acquire` 且 `status=TIMING_FAILED`。
  该字段与 `pkt TF`（全部路径的 TIMING_FAILED）分开列。
- 回放使用实时 pacing（737.28 MSps），2.0 s 数据 + 启动约 2.04–2.09 s/次：
  42 次（35 次 ABBA + 7 次 suspend）全部 `rc=0`、`raw_drop_samples=0`、`gaps=0`；
  另有 8 次 0.5 s CFO 注入回放全部 `rc=0`。
- 性能测量串行、同二进制、同主机；所有回放加 `sudo -n nice -n -10`。
  未做 core pinning / 固定频率；测量期间主工作树有并发构建，run-to-run 约 ±5–10%。
- **CFO 注入方法学**：先按 20 ms 块用最小二乘复投影估计并减去已知的 −232.96 MHz 单音
  （该单音严格为 −91/288 cycle/sample，288 点周期），残差单音幅度 < 1e-12；**再**注入
  ±100 kHz。第一轮“直接移频”把 LO 单音移到 −232.86 MHz，接收端固定 −232.96 MHz 消除器
  漏消，弱信号被淹没；该结果仅作对照（§8.3），不作为前端灵敏度结论。

## 3. 实现摘要（冻结版本）

### 3.1 算法

- **模板**：HRP Ipatov code 9–12 的 64 个非零 chip 映射到 750 点原生循环偏移
  `off = llround(8·c_i·48/65) % 750`，拆成 `+1`/`-1` 两张偏移表；稀疏相关为**纯加减、零乘法**。
- **折叠**：`K_coh=4` 个 SYNC 相干折叠（±100 kHz 理论 sinc² 损失约 −2.5 dB），
  `G_full=16` 组（64 符号）非相干功率累加；每组起点按
  `st = win_start + llround((g·K_coh+k)·750.276923…)` 精确重对齐；折叠缓冲线性双倍展开为
  1500 点，相关时无取模。
- **两级早停**：Stage-1 `G_fast=6` 组，`PAR >= 4.5` 才进入 Stage-2 补算剩余 10 组；
  Stage-2 `PAR >= 6.5` 才确认。`hop=128` 符号（步进约 96,035 样点），`stride=1` 全 750 lag。
- **码身份判决**：Stage-2 命中后，用**最后一次 `K_coh` 折叠**分别对 code 9–12 求单组 PAR，
  要求目标码 PAR ≥ `code_par_ratio_min=2.0` × 最强异码 PAR；这是同一折叠内的比值，
  对 SNR/CFO 同比缩放不敏感。绝对 `code_rho_min` 门限默认 0（关闭）。
  该门限**不是 CLI 参数**，本轮未改默认值。
- **前沿回溯**：命中后从窗口起点按 `16` 符号/步回退，最多 `preamble_reps=256` 符号，
  每步用 `K_coh=4, G_probe=4` 评估 `peak_tau` 三点峰值 vs 32 个非峰 lag，
  `probe_par >= 3.5` 继续回退，否则停止；提交 `seed = edge_pos + peak_tau`。
- **holdoff**：`holdoff_len=589,824` 样点（约 0.80 ms），命中后 `probe_` 推进到
  `max(probe+hop, holdoff)`。
- **SIMD 微优化（本轮唯一代码性能改动）**：`correlate_avx2` 由 8-wide 单块改为
  **2×8=16-wide 双路展开**：两个 lag 块共享同一组 tap-offset 读取，外层循环/寻址减半；
  每个 lane 仍使用 4 个部分和、按 `(a0+a1)+(a2+a3)` 合并，算术顺序与标量路径一致。
  `stride=1, K_coh=4, G_full=16, G_fast=6, hop=128` **均未改变**。热路径仍零分配。
- **参数调优结论**：`G_fast=4/5`、`hop=136/144/152/160/192` 都做过诊断；`G_fast=4/5` 与
  `hop=160` 在 −14 dB / ±100 kHz QA 中漏检，`G_fast=4 + hop=128` 虽通过默认网格的 10 次
  QA（203.5 ms），但相邻 hop 相位（136/144/160）即漏检，裕量不足。按“引入漏检即回退”
  的规则，**最终保持设计默认 `G_fast=6 / hop=128`**（§7.4）。

### 3.2 CLI 与兼容性

- `--acq-mode autocorr|xcorr`，**默认 `autocorr`**；默认路径、stdout 协议与既有 QA 保持不变。
- `--acq-xcorr-k-coh 4`、`--acq-xcorr-g-fast 6`、`--acq-xcorr-g-full 16`、
  `--acq-xcorr-hop 128`、`--acq-xcorr-par-fast 4.5`、`--acq-xcorr-par 6.5`。
- `--autocorr-when-locked scan|suspend|auto`（默认 `scan`）；`suspend` 在锁跟踪期间跳过
  xcorr/自相关扫描，失锁后回看再扫，要求 `--interference off`。
- 所有非法值在启动时 fail-closed；即使 `--acq-mode autocorr`，非法的 `--acq-xcorr-*` 也会被拒绝。
- 会话接入：`xcorr` 模式下用 `required_window_samples()` 驱动扫描，命中后复用既有
  `handle_autocorr_seed` / 锁状态机 / 候选窗口逻辑；gap 与 `AutocorrGate` 同步 reset 两个前端。

泄漏单音也移到 −232.86 MHz，接收端固定在 −232.96 MHz 的消除器漏消，弱信号被淹没。
本轮修正为：

1. 对 `clean_ch0` 与 `try2` 的前 0.5 s（368,640,000 样点），按 **20 ms 块**用最小二乘复投影
   估计并减去 −232.96 MHz 单音（严格 −91/288 cycle/sample，288 点周期）：
   `c = mean(x · exp(-j·2π·(-91/288)·n))`，`x' = x - c·exp(j·2π·(-91/288)·n)`；
2. **再**乘以 `exp(j·2π·df·n/737.28e6)` 注入 `df=+100 kHz`（try2 另做 `-100 kHz` 对称性）；
3. 写回交织 little-endian int16 SC16。

实测单音残差幅度 < 1e-12（块内复投影），RMS 从 clean 934.7→349.5、try2 982.5→304.4，
无 int16 削顶。

- **try2 −100 kHz**：B 99 种子、1/99 FCS、首帧 173.647 ms；A 0/569。左右不对称，

  证明“0 种子”由 LO 单音未去除造成。

### 8.3 诊断与结论

- 旧注入下 try2 的 −232.86 MHz 单音落在接收端固定消除器之外，弱信号被单音淹没；
  修正注入先去掉单音，B 立即恢复到 97/99 种子。**方法学修正改变了结论**：
  此前“try2 +100 kHz 前端 0 种子”不能作为前端灵敏度证据。
- 修正后 try2 仍 0–1 帧：失败首先在完整帧解调（PAYLOAD/SFD/TIMING），不是 acquire 不出种子；
  但也不能据此宣称 ±100 kHz 弱信号完整帧已达标。
- clean_ch0 的 B 在 +100 kHz 下首帧 1.433 ms、80/100 FCS，说明中强信号下 xcorr 对
  +100 kHz 是有效的；不能外推为“±100 kHz 全场景鲁棒”。

## 9. 局限与未验证项

1. **无硬件上板证据**：全部为文件回放；X410 实时链路、DW3000 射频、天线/信道、温度与
   长时间稳定性未验证。
2. **前端 CPU 未达标**：最终 270.7 ms/2 s（中位），显著高于 <200 ms。16-wide 微优化
   只带来约 −11%（单跑 306.9→272–275 ms）；`G_fast=4/5` 与 `hop=160` 都能把 CPU 压到
   200–235 ms，但 −14 dB/±100 kHz 裕量不足或直接漏检，已回退。该指标应作为后续
   kernel/结构优化项，不能标记为通过。
3. **灵敏度边界很薄**：QA 的 −14 dB/±100 kHz 是合成信号（10 次随机相位）；`G_fast=4`
   在默认 hop 网格 10/10，但相邻 hop 相位即漏检；`hop=160` 也漏检。说明 Stage-1 的
   24 符号相干增益是当前设计的必要裕量，不能仅凭一次 10/10 就外推到任意包到达相位。
4. **修正 CFO 后 try2 仍无完整帧**：+100 kHz 97 种子/0 帧、−100 kHz 99 种子/1 帧；
   acquire 已恢复，但后端 SFD/解调在 8.84 m + att 9.3 dB 弱信号下仍失败。不能把
   “有种子”写成“完整帧达标”。
5. **相对码门限 `code_par_ratio_min=2.0`**：Subagent-1 的 40 次合成 ROC 为
   −14 dB 平台模型 `2.0→33/40、1.75→37/40、1.5→39/40、1.25→40/40`，
   冲激模型 `2.0→24/40`；异码 Code9 高 SNR 下 ratio 最大 0.23。单组 64-tap PAR 的纯噪地板
   约 5.8–8.4，因此 2.0 在 −14 dB 边界天然不是 100%。**极端同窗强异码也可能同时抬高
   分母**（比值判决的固有风险）。本轮未改默认值；下一轮若要提高 −14 dB 检出，应在更多
   实采上评估 1.5–1.75，而不是直接改。
6. **前沿回溯的系统偏差**：QA 中 `seed` 比真实前导起点早约 **7501–7502 样点（≈10.0 SYNC）**，
   在 ±16 符号契约内，但会多消耗约 7.5 k 样点的 `pre_guard` 余量（36864 → 约 29.4 k）。
   本矩阵未因此出现 acquire TIMING_FAILED 增加，但更紧的保护/更高 CFO 下需复核。
7. **回放 pacing、并发负载与测量方差**：2.0 s 文件用实时 pacing，42 次运行 `raw_drop=0/gaps=0`；
   但测量期间主工作树有并发构建，未 pin、未固定频率，`frontend_scan_us` run-to-run 约 ±5–10%
   （同一 clean_ch0 默认配置可见 270–295 ms）。报告中的 270.7 ms 是 7 场景 ABBA 中位，
   不是严格的最坏/最好值。
8. **未做 MATLAB 逐样点交叉验证**；AVX-512 仅编译未运行；未上板；未 commit `testdata/`；
   本报告与实现均为本地提交，**未 push**。
