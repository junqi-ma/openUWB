### 2.3 try2 宽松锁定异常：证据链

这是本次唯一的功能性阻塞项。失败帧不是 SFD/时延失败，而是 **PHR 成功、payload 全败**：
每帧 `phr=1, len=127, fcs=0, path=target`，`st_payload=0`，`st_fallback≈2.3–2.6 ms`，
`cfo_rot_passes=4`（正常帧为 2），`chips≈215k`（正常 fused 前缀 ≈134k），`ondemand_fb=1`。
`cfo_init_hz≈−2.0 kHz`、`cfo_refit_hz≈−2.03 kHz`、`cfo_drift_rad=0.0`——CFO 估计本身正常。

为隔离因素，在 try2 上做了以下单变量回放（其余参数完全相同）：

| 变体 | 关键参数 | completed | FCS | 终态 | 4/5-pass 帧 | 结论 |
|---|---|---|---|---|---|---|
| 计划书宽松 | obs=2, holdover=500, reacq=1000, fcs=off | 415 / 414 | **0 (0.0%)** | verify | 264+1 | 复现阻塞 |
| holdover 改 3 | `--holdover 3 --reacquire 8` | 518 | 359 (69.3%) | **locked** | 2 | **holdover=500 是触发点** |
| 仅开 FCS | 宽松 + `--lock-fcs on` | 437 | 381 (87.2%) | **locked** | 0 | 默认锁定恢复 |
| obs 改 3 | obs=3，holdover 仍 500 | 416 | 0 (0.0%) | verify | 264+1 | 与 obs 数无关 |
| 关 CFO→SFO | `--sfo-from-cfo off` | 415 | 0 (0.0%) | verify | 257+6 | 排除 CFO 周期耦合 |
| 跳过 Stage-3 | `--cfo-refit skip` | 416 | 0 (0.0%) | verify | 264+1 | 排除 Stage-3 重估 |
| Stage-3 auto | `--cfo-refit auto` | 415 | 0 (0.0%) | verify | 264+1 | 同上 |
| 默认锁定 | 无覆盖 | 426 / 426 | 380 (89.2%) | locked | 0 | 达标 |

**旧树同命令日志给出了关键的路径排除**：该日志 426/426 帧同样
`sync_strategy=acquire_legacy`（`--sync acquire` 本来就不走 bounded ROI），但只有 10 帧
`PAYLOAD_FAILED`、370 帧完整 FCS；新树同命令是 264 帧 `PAYLOAD_FAILED`、0 帧完整 FCS。
因此不能把失败解释为“acquire 路径本来就不应解 payload”——旧树在同一条 acquire 路径上解出了 86.7%。

机制判断（基于代码与日志，未改代码验证）：`holdover=500` 使锁在 `Verify` 状态长期停留；`lock-fcs off`
的目标身份只靠网格残差，一旦个别观测被判 `identity_reject`，`verify_count` 无法连续攒到
`verify_observations`，锁既不进 `Locked` 也不落 `Reacquire` 重新锚定。所有帧因此走 acquire/verify 路径，
该路径在这一数据上触发宽 SFD 救援（`sfd_win=10, sfd_coarse=1152`）+ 全窗 soft-chip 回退，
最终 payload 失败。**这是锁状态机/acquire 路径的问题，不是 SFD-only 或种子统计口径问题。**

## 3. CFO 性能（Stage 2 + Stage 3）

### 3.1 字段含义（务必按此解读）

- `st_cfo`：Stage-2 **估计 + 首轮去旋转**的墙钟时间（`stage_cfo_us`）。
- `sfd_cforef`：SFD 锚定后的 Stage-3 **ML 重估 + 第二轮去旋转**（`stage_sfd_cfo_refit_us`）。
- `cfo_rot2_us`：第二轮去旋转本身（`cfo_refit_rotate_us`，是 `sfd_cforef` 的子项）。
- 因此 **Stage-3 估计器净耗时 = `sfd_cforef − cfo_rot2_us`**（按代码精确可分离）。
- **Stage-2 估计器净耗时 ≈ `st_cfo − 首轮旋转`**；首轮旋转量由
  `cfo_rot_ns_per_sample × cfo_rot_samples / 1000 − cfo_rot2_us` 近似（该字段是所有旋转的并集，
  含宽 SFD 救援/fallback 帧时不可精确分离，故只给 **P50/P95 与有效帧数**，不给 Mean）。
- `st_cfo` / `sfd_cforef` 都包含去旋转；计划书 §2.3 的 33 µs 模型只描述 ML 估计器本身，二者不能直接对比。

| Stage-2 估计器（路径 A，小 SFO） | ≤40 µs | **73–86 µs** | **不满足**（超 1.8–2.2×） |
| Stage-3 估计器（带 hint） | ≤40 µs（小 SFO）/ ≤60 µs（大 SFO） | **54–62 µs** | 不满足 40 µs；P50 落在 60 µs 内 |
| Stage-2 字段 `st_cfo`（含旋转） | ≤40 µs（小 SFO） | **83–99 µs** | **不满足** |
| Stage-3 字段 `sfd_cforef`（含旋转） | ≤60 µs（大 SFO） | **71–81 µs** | **不满足** |
| Stage-2 + Stage-3 估计器合计 | ≤40 / ≤60 µs（若按合计理解） | **≈127–148 µs** | **不满足**（超 2.1–3.7×） |
| 日志字段直接相加 `st_cfo+sfd_cforef` | ≤40 / ≤60 µs（若按字段理解） | **≈157–180 µs（含两轮旋转 ≈28–31 µs）** | **不满足** |
| 相对旧树同命令（try2 宽松） | 无明文预算（旧树 31 µs） | **170 µs（≈5.5×）** | 显著上升（见 §3.6） |

补充：计划书 §2.3 自己的模型是 Stage-2 33 µs + Stage-3 33 µs ≈ 66 µs，已经大于 60 µs；因此
“40/60”更可能是**单阶段/单路径**预算。按该解读，Stage-3 估计器 P50 多数落在 60 µs 内
（near200 宽松 62 µs 略超），但 Stage-2 始终不满足 40 µs。

**耗时结构推断**（未改代码验证）：Stage-2 在无 hint 时执行“64 符号粗窗 + 192 符号全窗”两次
`sample_sync_symbols_simd`，Stage-3 只执行一次 232 符号。实测差 ≈23 µs，与“每调用一次采样器
≈25 µs 固定开销 + ≈0.14 µs/符号”吻合。若 profile 证实，优化点是把模板/`SyncMatchedFilter`
的准备工作在两次 Stage-2 采样间复用，或在 timing 周期可信时跳过粗窗。仅靠 FFT/Newton 优化
无法把 Stage-2 从 ~80 µs 拉进 40 µs。

### 3.5 性能环境与噪声

- 串行：32 次回放严格一次一个进程；每轮墙钟 2.04–2.16 s（2 s 数据 + 启动）。
- 提权：并行门禁构建与回放共享主机。早期未提权的 campaign 出现过 `raw_drop_samples` 最高
  8.3×10⁸、`gaps` 上千；另一次 `--interference` 默认 on 的 smoke 出现 `completed=2540`。
  这两种轮次都不能与正式口径混用。正式 campaign 关闭 interference 并使用
  `sudo -n nice -n -10`，32/32 次 `raw_drop_samples=0`、`gaps=0`。
- 提权只影响 pacing 是否丢样和抢占尾部；对 P50 影响可忽略：未提权首轮（有丢样，仅作对照）
  clean 宽松 `st_cfo` P50=94 µs，提权后 92 µs。提权后仍保留少量 max≈1.3–1.6 ms 的抢占尖峰，
  因此表中同时给出 P95，且 `Mean` 会被这些尖峰抬高。
- 未做 core pinning、未固定频率；governor=performance，回放期最高 4679.9 MHz。

## 5. 风险与未做验证

### 5.1 风险（按优先级）

1. **try2 宽松锁定 0/415（阻塞）**：`holdover=500` 使锁停在 `Verify`，acquire/verify 路径上
   264 帧/轮 PHR 成功而 payload 全败，且 fused 与 soft-chip 回退都失败。已排除 CFO→SFO 耦合、
   Stage-3 重估、观测次数；旧树同命令日志（370/427，426/426 也是 acquire_legacy）表明旧树能解，
   剩余嫌疑在 verify 状态机/网格残差与 acquire payload 路径。建议用旧树二进制复测确认
   `holdover/obs` 后二分定位（锁状态机 vs 采样/去旋转路径）。
2. **性能不满足预算**：Stage-2 估计器 ≈73–86 µs（预算 40 µs；旧树同命令 `st_cfo`=16 µs），
   `st_cfo+sfd_cforef` 170 µs vs 旧树 31 µs（≈5.5×）。建议先 profile `estimate_cfo_ml` 的两次
   `sample_sync_symbols_simd` 调用，确认每调用 ≈25 µs 固定开销；再决定“复用采样器准备”
   或“跳过粗窗”。不要仅优化 FFT。
3. **默认锁定在 2.00/6.88 m 不进锁**：acquire+SIC 单窗口 compute_mean 达 3.9–7.2 ms（超过 2 worker×5 ms
   吞吐），导致 `dropped_queue` 900–1500。旧树同样不进锁，但本次队列溢出规模更大；若这两条距离
   要作为默认配置的验收点，需要单独处理锁获取策略或 acquire 预算。
4. **版本漂移**：主表是 `f49315b`，任务原文 HEAD 是 `da5e801`。clean/try2/jam 三组同参数 FCS 差 ≤2 帧（近距见附录 C），
   但正式验收报告应绑定一个确定的提交；建议 Coordinator 明确以哪个提交归档。
5. **失败标签迁移**：旧基线 `PAYLOAD_FAILED=6/9/4`，本次 clean/jam 的对应失败主要落在
   `SFD_FAILED`/`fcs_failed`。跨版本比较时应以“FCS 成功数”为主，不要逐标签对比。

### 5.2 未做的验证（必须显式列出）

- **MATLAB 逐样点/逐包交叉验证**：未做；`UWB_demodulation/` 的检测位置/CFO 结果没有与本次
  C++ 输出逐样点对齐。
- **上板实测**：未做；全部为文件回放，不能替代 X410 + DW3000 的实时/射频证据。
- **AVX-512 运行验证**：未做；本报告只运行 AVX2（`dev-avx2`）。`native-avx512` 仅由并行门禁编译，
  本机无 AVX-512 运行环境。
- **大 SFO / 分数网格（路径 B）**：本次实采 |SFO|≈0.31–0.33 ppm，只走整数路径 A；4-lag
  Catmull-Rom 路径的耗时与正确性没有实测。
- **其他 HRP code / 前导长度**：只测 code10 / 256-SYNC / 4z2；code9–12、64-SYNC、16-SYNC 未覆盖。
- **长时间/热稳定/多 worker**：只跑 2 s、2 worker；4 worker、长时运行、温度/降频未测。
- **TWR / Sensing / SIC 深度**：不在本报告范围；SIC 只作为 jammer 数据的既有参数使用，未评估
  SIC 自身精度。
- **与旧二进制的同参数 A/B**：没有重新构建旧二进制做实时 A/B（边界只允许本报告写入，旧构建未保留）；
