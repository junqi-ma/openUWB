# Timing 原语收口重构验收报告（2026-11-21）

**分支/Worktree**：`feature/openuwb-timing-refactor`（基于 `7dcc3f2`）
**范围**：`openuwb::timing` support 层时间测量原语收口——新原语 + 全库去重接线，
"行为零变化"重构。不含 Phase C（`--perf-report` JSON）与 Phase D（Tracy 集成），
两者为后续独立任务（见 §6）。

## 1. 层位裁定（编译结构推导）

域依赖单向 DAG（`lib/CMakeLists.txt`）为 `support → dsp → phy_hrp → {sic,sensing,twr_core}`，
`runtime → phy_hrp + sic + sensing + radio`。计时插桩的实际消费者横跨 dsp/phy/sic/radio/runtime/apps/tests
全部层，因此原语唯一合法落点是 **`openuwb_support`**（header-only，零新编译单元、零 CMake 目标）：

| 新文件 | 内容 |
| :--- | :--- |
| `include/openuwb/support/timing.h` | `Clock`（=`steady_clock`）、`now()`、`elapsed_ns(a,b)`、`elapsed_us_since(t0)`（payload 口径截断）、`elapsed_us_f(a,b)`、`accumulate_ns(atomic&,t0)`（relaxed fetch_add）、`thread_cpu_ns()`（`CLOCK_THREAD_CPUTIME_ID`，无该时钟平台回退 0）、`ScopedNs<Enabled>` RAII（`Enabled=false` 空类特化） |
| `include/openuwb/support/timing_config.h.in` | CMake 生成 `UWB_TIMING_ENABLED_DEFAULT`（0/1），与 `simd_config.h` 同构的 ODR 防护 |

职责分层裁定：**原语在 support；阶段语义（`resample_end/sic_end/demod_end/compute_end` 等字段名与加性
桶契约）留在 runtime/phy；消费（ABBA、分位数、JSON 摘要）留在 apps/tools**。阶段字段名是
runner_summary.json 与 stdout 控制台契约的一部分，绝不动。

## 2. 契约

- `elapsed_ns` / `elapsed_us_since` 保留被替换代码的 **`duration_cast` 截断语义**，逐字段数值不变。
- `accumulate_ns` = `fetch_add(relaxed)`，无锁无分配，沿用 scheduled_pipeline / fixed_tone_cancel 的
  累计模式；时钟读位置与次数不变。
- `UWB_ENABLE_TIMING`（默认 ON，`UWB_TIMING_ENABLED_DEFAULT=1`）只控制 `ScopedNs<>` 的模板默认值；
  **原语永不编译移除**（阶段边界契约依赖它们存在）。OFF 构建里库 TU 无 `ScopedNs` 消费者，
  见 §4 的 .o 逐字节对照。
- support 层 baseline-ISA 约束保持：timing.h 纯 `<chrono>`/`<ctime>`，不用 SIMD/Volk，
  `openuwb_support` 仍然不做 `uwb_simd_apply()`。

**行为零差异核验（目标文件对照，`compile_commands.json` 同旗标复编）**：

- `lib/runtime/scheduled_pipeline.cc`、`lib/radio/uwb_fixed_tone_cancel_source.cc`：
  HEAD 源码与重构源码在**同一新头文件/同参数**下编译出的 `.o` **逐字节一致**（差异仅为对比脚本的临时文件名）。
- `apps/live_rx_session.cc`：反汇编存在指令布局差异，全部来自 `thread_cpu_us()` 的运算次序变化——
  旧实现 `tv_sec*1e6 + tv_nsec/1e3`（纯 double 两步舍入）→ 新实现 `uint64 精确 ns → double /1e3`
  （单次舍入，精度**更高**）；该值仅在控制台以默认 6 位有效数字打印（`console_reporter.h:283`），
  ~10⁻¹³ µs 量级的舍入差异不可见。`elapsed_us()` 与旧公式在浮点语义上恒等（`std::micro` duration 相同）。
- ON/OFF 两种默认下库归档无差异的论据：库内 TU 尚无 `ScopedNs<>` 消费者（设计意图，见 §5），
  两个构建树相应 `.o` 一致。

## 5. 已声明的边界

- 本轮**未做** ABBA 运行时性能对拍：被替换助手与新原语在 `-O3` 下内联为同一 `duration_cast`
  指令序列且时钟调用点位置/次数不变，上节的核心 TU `.o` 逐字节对照给出了比抽样更强的证明；
  `live_rx_session.cc` 除外（`thread_cpu_us` 精度改善，见 §4，不可见于控制台精度）。
- `UWB_ENABLE_TIMING=OFF` 目前对库无可观测差异（库内还没有 `ScopedNs` 消费者）：它是给后续
  Phase C/D 埋的编译期开关，本轮只验证其可构建性。
- `qa_uwb_uwb_timing.cc` 中涉及时钟的用例一律断言单侧不变量（测量 ≥ 自旋时长、子区间 ≤ 外区间），
  不含壁钟绝对值，CI 负载下稳定。
