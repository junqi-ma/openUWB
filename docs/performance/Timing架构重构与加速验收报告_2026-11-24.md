## 3. 三项零损加速

### 3.1 优化 A：低 SNR 局部 K=4 折叠前置

插入点：`acquire_unbounded_seed()` 中，narrow seed 精搜与 legacy ±256 精搜**均未命中之后**，
wide interval probe / TM-1 / coarse scan / 全网格 / 完整 fold **之前**。

触发条件：`AcquireLegacy && seed_start >= 0 && !rx_wide_interval_probe`（无 seed 盲搜与 SIC
宽窗快失败路径完全不变）。动作：`seed ± min(margin, 8192)` 上一次 K=4 相干折叠，仅 1016 lag，
不调用 `probe_fold_phase`、不跑 K=64。

接受门限（**全部**满足）：
1. `fold_acquire` 通过既有 `kFoldThreshold = 0.05` 或 `PAR ≥ 12.5 dB`；
2. 前沿消歧 `disambiguate_fold_leading_edge` 找到有效前沿（`max_here ≥ 0.003f`）；
3. **扫描边界守卫**：`edge.start > fold.start − (radius/P + 2)·P`。若交叉落在扫描窗第一个
   候选（即真实前沿在窗外，典型为种子深入前导 >9 SYMBOL），**拒绝**并回退；
4. `fold_anchor_fit` 成功且 `≥4` 锚点、锚点中位数 `≥ 0.08`（`kFoldFastAnchorMedianFloor`，
   幅度归一化度量；16 组 K=4 锚点在 −12/−14 dB 约 0.3–0.5，4 符号折叠噪声约 0.045）。

任一不满足即清空已写入的 `out.peak_*` 并无缝落入原路径。**实测拒绝分布**（clean 8.84 m，
426 次调用）：命中 336 次；`fold` 指标 < 0.05 拒绝 62 次；锚点中位数 < 0.08 拒绝 59 次。
两类拒绝均为真实弱包，全部由原 coarse/全网格/K=64 兜底救回（FCS 仍 ≥ 基线）。

### 3.2 优化 B：`fold_anchor_fit` 稀疏锚点

- 周期/原点拟合（第一遍）**仍测量全部 `groups` 组**（256 前导 = 64 组）。这一点在验收中被
  证明不可省略：**只测 16 组时 `try2` 宽松锁定整组崩溃（0/416、PF=253）**，因为锁定反馈
  与 SFD 锚定重定时对 16 点拟合的截距噪声敏感（详见 §5.2）。
- 第二遍（逐组 ±refine 重折叠 + 相关 + 输出 `peak_samples`）改为在 `[0, groups−1]` 上
  **均匀稀疏 16 组（含首尾）**，索引
  `g_sel[i] = round(i·(groups−1)/(n_anchors−1))`，256 前导得
  `[0,4,8,13,17,21,25,29,34,38,42,46,50,55,59,63]`。
- 第二遍的标量能量循环 `for (k<L) rx_energy += std::norm(sup[k]);` 替换为
  `window_power_8acc(sup.data(), L)`（8 累加器、可向量化的既有原语），**消除标量能量循环**。
- `lock_integer_grid` 判据与拦截距换算仍基于**全跨度** `(groups−1)·4`，与旧 64 组拟合完全一致。
- 因此 `detected_peaks` 对 256 前导为 **16**（≤16 契约满足），且仍跨满 252 SYMBOL 基线。
  64 重复默认前导（`groups = 16`）时每组都测，**与基线逐位一致**。

### 3.3 优化 C：共享模板缓存 + 热路径零堆分配

- 抽出 `detail::ensure_shaped_sparse_template_cached()`（`demod_sync.h`），用
  `(8 点采样探针, 指针, 长度, code.key)` 身份替代每包 1016 点全量 FNV-1a 哈希；Stage-1 与
  CFO 采样器共用同一缓存条目（`demod_scratch.h` 新增 `cfo_template_code_key`）。
- 三处隐式堆分配改为 `DemodScratch` 复用：`cand_metric` → `timing_fold_cand_metrics`，
  `lag_metrics` → `timing_fold_lag_metrics`，`peak_indices` → `timing_peak_indices`。
- 新增单测 `test_timing_k4_fast_path_warm_call_does_not_grow_scratch`：核对 16 个 scratch
  缓冲的 `capacity()` 在第二次（热）调用前后完全不变。

## 4. 连接点修复：稀疏锚点带来的 CFO 相位混叠（必要项）

稀疏 16 锚点使 Stage-2 `fit_cfo()` 的相位展开在锚点间距（16/20 SYMBOL）下发生混叠
（±40 kHz 会被折到 ~−18 kHz）。这是拆分后**实测暴露**的问题：`qa_uwb_radar_timing_core`
的 `test_low_snr_fold_resolves_sparse_anchor_cfo_alias`（±40 kHz）在基线 HEAD 就因
`detected_peaks = 64` 失败，而 16 锚点若不加处理会把 ±40 kHz 估成 ~58 kHz。

最终采用**双轨**方案（不改任何 QA 契约、不引入不可靠的相位提示）：

1. **影子稠密 CFO 网格**：`fold_anchor_fit` 在拟合网格上为**全部 `groups` 组**（256 前导 64 组，
   间隔 4 SYMBOL）各做一次重折叠 + 单点相关（不做 ±refine 搜索），写入
   `scratch.timing_fold_cfo_samples/corr`。Stage-2 `fit_cfo()` 在 `sync_peaks_folded` 且该影子
   网格 ≥4 点时优先消费它——这正是基线 64 锚点给交叉校验的信息量（相对 `cfo_min_fit_repetitions`
   =32 的 24 符号启动跳过仍余 40 点），且 4 符号间隔使相位展开在 ±122.8 kHz 内无混叠。
   公开 `TimingResult.peak_samples/peak_corr` 仍为稀疏 16，`detected_peaks ≤ 16` 契约不变。
2. **通用稀疏回退**：`fit_cfo()` 在相邻间隔 ≥ 4.5 SYMBOL（真正的稀疏序列）时，按锚点间隔的
   **GCD** 推导无混叠半径（`fs/(2·gcd·4P)`），在峰度（periodogram 相干和）上粗搜+细化选支，
   再做既有 OLS 精估。均匀 16-SYMBOL 合成序列（gcd=4 组 → ±30.7 kHz）与 256 前导混合 16/20
   SYMBOL（gcd=1 组 → ±122.8 kHz）均正确。

效果：CFO 精度与基线一致（|cfo| 均值 1.98 kHz vs 1.98 kHz），`try2` 宽松锁定与 ±40 kHz
专项回归全绿（见 §5）。

## 8. 未覆盖项与风险

1. **未上板**：全部为文件回放；`st_timing` 降幅未在实板实时链路复核。
2. **AVX-512 仅编译**：本机虽有 AVX-512 硬件标志，但预设未启用；未做 AVX-512 实机运行与
   性能测量。
3. **AVX-512 路径下的折叠引擎**：`fold_accumulate` 的旋转分支用 AVX2，未单独验证 AVX-512
   分发下的逐位一致性（既有 QA 在 scalar/AVX2 下全绿）。
4. **快路径未命中率**：clean 8.84 m 约 15% 包仍走 coarse 兜底（`fold` 指标 <0.05 或锚点
   中位数 <0.08），本报告按 P50 口径验收；P95 `st_timing` 仍达 ~650 µs，未做 P99 统计。
5. **`fit_cfo` 稀疏回退的峰度搜索**：对 ±120 kHz 之外的 CFO（超出 Stage-2 规格）不做保证；
   仅在 `sync_peaks_folded && 影子网格 ≥4` 或间隔 ≥4.5 SYMBOL 时启用，常规路径不受影响。
6. **`near506` 的 FCS 与 completed 波动**：基线与重构侧 `completed` 分别为 465.5/430.5，
   FCS 绝对数 387.5/394.5 的差异主要来自完成窗口数差异，属历史已知的该数据集波动
   （CFO 报告同样记录该组 ~90% 且对启动窗敏感），不作为本次退化证据。
7. **未做 MATLAB 交叉验证**：本次改动为架构与计算路径重构，未改变检测/解调算法语义；
   `--timing-sparse on` 低 SNR 检测损失等既有 MATLAB 待办仍在 `开发状态.md` 中保留。

## 10. 附注（2026-11-24 复核轮：快路径折叠去重与拒绝路径清理）

在最终 A/B 之后又做了一轮**纯计算路径**微调，不改变任何验收指标语义：

1. **`fold_anchor_fit` 单次重折叠**：原实现「公开 16 组」与「影子稠密 64 组」两个循环分开，
   使 16 个 `g_sel` 组被 `fold_accumulate + filter.dot` 折了两遍（最坏 `n_sel + groups` = 80 组）。
   现合并为一次遍历：请求影子网格时按 `g = 0..groups-1` 走一遍，每组相关值同时写入影子网格，
   命中 `g_sel` 时再用 `window_power_8acc` 算 `metric` 写入公开 `peak_*`；未请求影子网格时
   仍只走 `n_sel`（≤16）组。`peak_*` 与 `cfo_peak_*` 的取值、顺序与旧的两次遍历逐位一致，
   `peak_samples.size() < 2` 失败时同步清空影子网格（与入口清理对称），热路径仍零堆分配。
2. **快路径拒绝清理**：`try_fold_acquire` 的 `fast_only` 两个（拟合后）拒绝分支在清空
   `out.peak_*` 的同时清空 `scratch.timing_fold_cfo_samples / timing_fold_cfo_corr`，
   避免失败的快路径把半成品影子网格留给 `fit_cfo()`。
