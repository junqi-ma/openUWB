# 固定单音消除加速与锁后按需对消验收报告（2026-11-24）

> 范围：`FixedToneCancelCore` / `FixedToneCancelSc16Source` 热路径与
> `openuwb_rx` 的锁后消费策略。**未改**解调、重采样、SIC、TWR、Radar 算法。
> **全部数据为离线文件回放（`raw_2s.sc16`，2.0 s，737.28 MS/s），不含上板实测。**

## 2. Phase 1：核内微优化

### 2.1 实现

`lib/dsp/uwb_fixed_tone_cancel_core.cc` 新增
`copy_cancel_loop_avx2()`（`__attribute__((target("avx2")))`）：

- 把 `while (pos < n)` 周期游走整体放进 AVX2 函数，`copy_cancel()` 每次调用只
  经过 **1 次**间接调用，而不是每 288 样点 1 次（2 s 流由 ~512 万次降为按块 2 万次级）。
- 周期主体 **4× 展开**（4×32 B = 128 B/步 = 32 个复数样点），且每个向量的
  load/sub/store **逐向量交错**。实测“先 4 个 load 再 4 个 store”的分组写法在
  2 s 回放上慢 3–6%，因此采用交错顺序。
- `period % 8 == 0` 时主体无尾部；非对齐相位（`lut_pos != 0`）与末尾不足一个周期
  分别用一次前导/尾段处理，仍与 `subtract_sat_scalar` **逐位一致**。
- crossfade / bypass / training 语义完全未动；in-place 与 out-of-place 都覆盖。

### 2.2 微基准（`benchmark_fixed_tone_cancel`，单核、无 UHD/队列/DSP 竞争）

| 单元 | 优化前 fused | 优化后 fused | 变化 |
|---|---|---|---|
| 16384 样点（单次读块） | 1.727 µs | 1.423–1.457 µs | −16% ~ −18% |
| 65536 样点（默认 raw block） | 6.514 µs | 5.377–5.806 µs | −11% ~ −17% |
| 14745600 样点（整 20 ms） | 6832.98 µs | 5052.55–5093.12 µs | −25% ~ −26% |

每轮 9 次 ABBA 配对中位数；fused 与 two-pass 输出逐字节相同断言保持。

### 2.3 生产回放 ABBA（Arm 1：`--autocorr-when-locked suspend --tone-when-locked full`）

| 场景 | 优化前 `cancel_us`（4 轮均值） | 优化后（4 轮均值） | 变化 |
|---|---|---|---|
| `clean_ch0` | 373.1 ms | 369.9 ms | −0.9% |
| `jam688`（+SIC） | 403.9 ms | 389.7 ms | −3.5% |

回放数据与微基准的差异说明：**流式路径是 DRAM 带宽受限**，核内指令数不是瓶颈。
另外两种写法作为对照被否决：整段单向量核与逐周期调用持平；分组 4× 展开慢 6%
（`clean_ch0` 368→390 ms）。最终采用的交错 4× 是唯一不劣化且微基准最快的写法。

### 2.4 `cancel_us` 归因（不猜，实测）

- Arm 1 的 `cancel_us` ≈ 370 ms 对应 2 s 内 **读 5.9 GB + 写 5.9 GB**
  （`cancelled_samples=1474560000`；写目标为 8 MiB 环形区，实际含 RFO 约 17.7 GB
  DRAM 流量，≈48 GB/s，接近本机单线程流式上限）。
- 核内计算部分由微基准折算：65536 样点 5.4 µs × 22500 块 ≈ **121 ms（约 33%）**；
  其余 ~250 ms 是目标写回/冷页/TLB 与后台 DSP 竞争，不是函数调用开销。
- `--tone off` 对照：`cancel_us=0`、`reader_us=0`（无 decorator），FCS 仍 400/400；
  说明这 5.9 GB 环形写入在正常读路径本来就存在，`cancel_us` 的增量主要是
  “raw ring→ring 的搬移 + 逐样点相减”。

因此 Phase 1 的收益主要在缓存驻留/整周期批量场景（微基准 −25%），
2 s 流式场景只有 1–3.5%；**真正的 2 s 收益来自 Phase 2 的免拷贝跳过**。

## 3. Phase 2：锁后静默期零拷贝跳过（opt-in）

### 3.1 `FixedToneCancelSc16Source::skip_samples()`

`read_samples()` 与 `skip_samples()` 共用新的私有 `produce(..., bool cancel)`：

- 复用**完全相同**的 epoch / gap / 20 ms 训练状态机；每 20 ms 的 0.5 ms 训练窗
  仍从 raw ring 折叠并提交 LUT + crossfade。
- `cancel == false` 时**不调用** `copy_cancel()`、不写调用方 `dest`，只推进
  `cur_offset` / `tail` 释放 raw block。
- 新统计：`skipped_samples`、`skip_calls`、`skip_us`；**绝不混入**
  `bypassed_samples`。`consumed_samples` 仍计入被跳过的样点，保持
  `queued = consumed + pending` 守恒。
- 训练窗边界/周期边界照常截断；遇到带 `is_gap` 标记的块起点时返回
  `n == 0 + meta.is_gap`，由调用方回退到 `read_samples()` 统一上报缺口并重置
  epoch（模型轴保持单一真源，不存在双次对消或跨线程 LUT 访问）。

### 3.2 live 接入（`apps/live_rx_session.cc`）

`--tone-when-locked window` 且同时满足以下条件时按块跳过：

- `lock.state() == Locked`（严格 Locked，Holdover/Reacquire 立即停止跳过）；
- `autocorr_gate.suspended`（前端扫描确已暂停）；
- 无待提交的 acquire/deferred 窗口（`pending_seed < 0 && pending.empty()`）；
- 预算 `skip_budget = min(下一次计划窗 window_start, 已挂起待填计划窗 window_start) - 1×block - end > 0`。

跳过时：`end += n`，`valid_begin = end`（显式让环形区内的旧数据失效，任何扫描/
窗口裁剪都不会误读）；进入目标窗覆盖区、失锁、gap 或存在待提交窗口时立即回到
`read_samples()` 全量对消。`tone_skip_us` 实测 0.99–1.17 ms/2 s（跳过记账成本可忽略）。

`COST_TOTAL` **仅在 window 模式**追加
`tone_skipped_samples=... tone_skip_us=...`；`full`（默认）的 stdout 字段序列与
改动前逐字段一致（已用键序列 diff 验证）。

### 3.3 CLI 与 fail-closed

- `--tone-when-locked full|window`，默认 `full`。
- 非法值、`window` 但未开 `--autocorr-when-locked suspend`、`window` + `--mode timed`
  均在启动时抛错退出，不静默回退。

## 6. Holdover / Reacquire 恢复（Arm 2，无 SIC）

| 场景 | Arm | `fcs_ok` | 最终状态 | holdover | reacquire | dropQ | `cancel_us` |
|---|---|---|---|---|---|---|---|
| jam506 | 2 | 128 | locked | 40 | 1 | 0 | 146.5 ms |
| jam506 | 1 | 127 | locked | 41 | 0 | 0 | 425 ms |
| jam506 | 0 | 127 | verify | 40 | 1 | 0 | 415 ms |
| jam688 | 2 | 51 | holdover | 49 | 0 | 0 | 279 ms |
| jam688 | 1 | 51 | holdover | 46 | 1 | 0 | 449 ms |
| jam688 | 0 | 51 | holdover | 46 | 1 | 0 | 444 ms |

`jam506` 在 Arm 2 下经历失锁（holdover→reacquire）后**重新回到 locked**，FCS
不低于基线；`cancel_us` 回升到 146 ms 正是“失锁即切回全流对消”的预期行为

51/400（与本轮改动无关，Arm 0/1/2 完全相同）。

## 9. 偏差与注意事项

1. **4× 展开采用 load/sub/store 交错顺序**。题目描述的分组顺序（4 个 load →
   4 个 store）经实测在 2 s 回放上慢 3–6%，未采用；交错 4× 同时满足“整段核 +
   4× 展开 + 逐位一致”，且微基准最快。
2. `COST_TOTAL` 中带 `_us` 后缀的字段单位是**微秒**；`frontend_scan_us` 在
   Arm 0 约 267 ms，在 suspend 下约 2–4 ms。
3. `--tone-when-locked window` 与 `--tone off` 同时出现时不会跳过（没有
   decorator），只打印 `tone_skipped_samples=0`；未额外把它升级为启动错误。
4. 本报告全部为**离线文件回放**；未做上板、未声明 737.28 MS/s 实时余量。
   `testdata/dw3000_*` 未提交（保持在工作区）。
5. 初次冷页缓存运行会出现 `raw_drop_samples>0` 与 FCS 下降，属于 I/O 抖动，
   矩阵已先做一次预热并丢弃该轮。
