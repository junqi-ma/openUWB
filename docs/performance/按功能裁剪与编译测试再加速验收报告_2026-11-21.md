### 1.4 flake 修复

- `qa_uwb_fixed_tone_cancel_source.cc`：
  - 环形缓冲容量按“队列槽位数 × 单次读取样本数”计算。原测试按总样本数设
    `block=1024, queue=16`，但实际读取 256/97/31 样本，容量不足。
  - 将零丢包断言的用例提升到 `queue=512`，并按最坏分块数覆盖整段流。
  - dump 目录加入进程唯一后缀，消除跨构建树/并发运行的 `/tmp` 目录竞争。
  - 20 路并发复跑 20/20 通过；3 轮全量 `ctest -j20` 通过。
- `qa_uwb_uhd_sc16_pipeline.cc`：多核停止用例不再固定 `sleep 5 ms`，改为有界等待
  首个窗口（最多 2 s），避免满载调度下 `offered_windows==0` 的假失败。

### 2.3 ccache + mold（用户级安装，2026-11-21 补测）

本机无 root，使用用户级安装：ccache 4.14.3 官方 musl-static 包解包到
`~/.local/opt/ccache-4.14.3`；mold 1.0.3 与 lld 14 从 Ubuntu 源下载 `.deb` 后
`dpkg-deb -x` 到 `~/.local/opt`；入口脚本放在 `~/.local/bin`。CMake 自动探测到
`ccache + PCH + GCC` 时追加 `-fpch-preprocess`，否则 PCH 消费 TU 会被 ccache
标记为 uncacheable。

| 构建 | 墙钟 | ccache 统计 |
| :--- | ---: | :--- |
| 冷缓存全量（最终代码） | 34.2 s | 115/115 可缓存，0 命中 |
| 同参数新目录热缓存全量 | **2.12 s** | 115/115 direct hit |
| 旧版无 ccache 基线 | 38.3 s | 未启用 ccache |

- `mold` 链接已验证：`build.ninja` 中出现 `-fuse-ld=mold`，全量 CTest 通过。
- 冷缓存比无缓存慢约 13%（`-fpch-preprocess` 与缓存写盘），但一次热缓存即可
  回本；跨 preset / worktree 的重复全量构建收益最大。
- ccache 配置：`max_size=10G`、`sloppiness=pch_defines,time_macros`、
  `hash_dir=false`、`base_dir=<repo>`，使不同 build 目录共享条目。

## 4. 已知边界与后续建议

1. **未上板**：本报告全部为构建、回放与单元 QA 数据，不构成 ToA/测距/硬件证据。
2. **AVX-512**：本机仅能编译，无法运行宽内核；`native-avx512` 未做运行时验证。
3. **ccache**：宿主未安装 ccache，跨分支/多 build 目录的缓存收益未计入；安装后
   `UWB_USE_CCACHE=ON` 会自动启用。
4. **MATLAB 交叉验证**：本轮未新增检测位置逐样点 MATLAB 对拍；既有 golden 用例
   保持原容差通过。
5. **静态库重链**：若需要进一步降低“改库实现”的重链成本，日常开发建议使用
   `UWB_DEV_SCOPE=<domain>` + `UWB_DEV_SHARED_LIBS=ON`；交付/CI 仍使用
   `UWB_DEV_SCOPE=all` 与静态库。
