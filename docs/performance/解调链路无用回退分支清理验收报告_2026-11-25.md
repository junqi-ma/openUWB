> **证据边界（必读）**：本报告全部数据来自仓库 `testdata/` 下 2026-11-23 实采 SC16 文件的

> **不是上板实测**；未做 MATLAB 逐样点交叉验证；未做 TWR/ToA 验证。
> 文中 “FCS 成功” 均指 `PACKET status=OK && fcs=1` 的完整帧，不包含 SFD-only/PHR-only/前导种子数。

- 执行方案：[OpenCode 执行方案：解调链路（Timing / SFD / CFO / Payload）无用回退分支清理与重构](OpenCode执行方案_解调链路无用回退分支清理与重构_2026-11-25.md)

- 结论：**Phase 1 / 2 / 3 全部落地并通过全部门禁；Phase 4（CFO Stage-2 去交叉检查）经实测否决并保持原样。**

## 2. Phase 明细

### 2.1 Phase 1（`e94d06d`，+63 / −130）

- `SfdAnchorConfig` 由 8 字段精简为 `full_repetitions / bootstrap_sfd_start / period_hint /
  template_len`；删除 `tail_repetitions / tail_first / tail_start / cfo_anchor_profile` 的
  构造与 7 个 profile 字段拷贝。下游 `build_sfd_anchored_timing()` 与
  `refit_tail_cfo_and_rotate_anchored_prefix()` 逐字段核实只读取保留的 4 个字段。
- 空壳 `run_tail_retrack_and_cfo_refit()`（`(void)seed_radius;` + 两行转发）删除，并入调用点。
- 公共头字段 `Qm35825Profile::rx_seed_refine_tail`、`DemodResult::stage_sfd_tail_retrack_us`、
  `stage_tail_retrack_fallbacks` 保留并标注退役（后两者恒为 0），`console_reporter.h` /
  benchmark / QA 零改动。
- `fold_anchor_fit()` 的 dense-CFO-grid 与 sparse-only 两条重折叠循环合并为
  `refold_and_dot()` + `corr_metric()`，`fill → fold_accumulate → filter.dot →
  window_power_8acc` 的调用顺序、条件（仅 `selected` 时算 power）与 push 顺序不变。

> **偏差说明**：方案称 `rx_seed_refine_tail` “恒为 0”，实际 `apps/live_rx_session.cc`、
> SIC 与 `benchmark_fullpacket_compare` 仍会置 true；清理后它只是不再被解调器读取，
> 按“调用方零改动”保留。

### 2.2 Phase 1-C（`01ca615`，+1 / −56）

`compute_fused_payload_rotation_range()` 全仓核实仅被
`tests/unit/phy/qa_uwb_refactor_contracts.cc:318-325` 引用，生产走
`compute_anchored_prefix_range()` / `compute_ondemand_extension_rotation_range()`。
删除声明、实现与该段唯一废弃契约断言（同时删除随之失效的 `ns_sfd`/`phr` 构造），
其余断言未动。

### 2.3 Phase 2（`a16e43c`，+256 / −182）

- **P2-A**：删除 `stage_payload_fused_cmf()` 中 `known_hop && !sfo_track` 的 M0
  4-candidate 重放安全网。失败直接 `return false`，外层
  `run_on_demand_with_full_stream_fallback()` 契约与 `stage_fused_fallbacks` 统计不变。
  （该安全网在 M4 生产配置 `rx_fused_sfo_track=true` 下本就不执行，删之无行为影响。）
- **P2-B**：新增 `joint_ml_ran`，仅在其为 false（M0/M1/非 fused PHR）时执行 Split-LLR
  Attempt 3；joint ML 已跑时跳过。
- **P2-C**：`stage_payload_fcs()` 只重试 `L = phr.psdu_length`，保留
  `pols[2] = {pol0, -pol0}`；循环内 `std::vector` 全部提到极性循环外复用；
  增加与 fused 路径一致的 `psdu_length > max_psdu_bytes` 早退。
- 新增只读诊断计数 `PayloadSubTimers::fused_metric_passes` / `legacy_soft_rounds`
  （未接入 stdout/benchmark schema），并新增两条单测：
  `fused_payload_bad_packet_skips_four_candidate_replay`（坏包只做 1 次融合相关）、
  `test_demod_core_r4_payload_soft_retry_only_reported_length`（每极性仅 1 轮，共 2 轮）。

### 2.4 Phase 3（`ffb0958`，+86 / −126）

- **P3-A**：删除 `acquire_unbounded_seed()` 的 TM-1 相位探测块（含 `probe_gate` 预门）与
  Whole-SYNC 全符号网格探测块。主干收敛为：窄窗 seed refine → ±256 PAR seed refine →
  局部 K=4 fast fold → wide interval probe → coarse scan + fine refine → 全量 K=4/K=64 fold。
- **P3-B**：删除 `acquire_locked_bounded()` 折叠全部失败后的宽窗 `tail_sweep(roi)`。
  保留 `tail_sweep(min(roi,32))`、`try_fold_acquire(..., roi, false)`、
  `locked_tail_probe == false` 硬失败契约，以及 `track_locked_grid` 失败回退 `track_sync_train`。
- 新增 `test_locked_bounded_pure_noise_does_not_wide_tail_sweep`：纯噪声 `LockedBounded`
  断言 `tail_probe_attempts == 32`。**旧实现实测 64 并失败，新实现 32 通过**
  （实现者已用临时还原旧文件的方式验证该用例确实能拦住回退）。

## 5. Phase 4（CFO Stage-2 交叉检查）诊断与结论

### 5.1 方法

在独立 worktree 中给 `run_initial_cfo_and_bootstrap_sfd()` 加环境变量门控：
保留 `fit_cfo()` 的计算，但可选择“只记录、不应用”，从而在同一二进制内对照
“有交叉检查 / 无交叉检查”两种行为，并统计 `|ML − legacy| > max(2 kHz, 5%)` 的触发次数。

> 过程修正：首轮诊断经 `sudo` 启动，`sudo` 默认 `env_reset` 吞掉了 `OPENUWB_P4A_DIAG`，
> 导致 A/B 实际跑同一路径、错误地得到 “0 触发”。改用 `sudo -n -E` 后获得下表有效数据。
> 该无效轮次仅用于发现方法缺陷，未进入结论。

### 5.2 有效触发数据（各 1 轮）

| 场景 | 交叉检查触发次数 | 移除后的最终状态 / FCS |
|---|---:|---|
| clean884 | 4 / 427 包 | locked，FCS 不变（395/427） |
| try2（默认锁定） | 5 / 424 包 | locked，FCS 不变（390/424） |
| **try2_loose** | **9 / 413 包** | **verify，0/413（基线 390/429–433）** |
| jam884 | 1 / 607 包 | holdover，FCS 不变（47/607） |
| near506 | 0 / 430 包 | locked，FCS 不变（129/430） |

典型触发样本：

```text
P4A_WOULD_CORRECT ml=-1584.0 legacy=-27177.2 diff=25593.2 tol=2000.0 folded=1 mlpk=64 lpks=40
P4A_WOULD_CORRECT ml=-1381.3 legacy=-4176.2  diff=2795.0  tol=2000.0 folded=1 mlpk=64 lpks=40
```

### 5.3 结论

- 触发率**不为 0**：在 `try2` 宽松锁定上每个文件的 413 个提交窗中触发 9 次，
  且 `mlpk=64`（ML 用满 64 符号）说明是 ML 锚点偏移而非样本不足。
- 移除交叉检查后 `try2` 宽松锁定 6/6 轮均为 `0/41x`、`final_state=verify`，
  完全复现历史注释描述的“`bootstrap SFD` 被旋出 ±64 样点窗”故障。
- 按方案 §3 Phase 4 “回退准则”，**立即放弃 P4-A**，永久保留 `fit_cfo()` 交叉检查。
- **影子稠密 CFO 网格同样保留**：P1-B 之后 dense 网格与 sparse 峰值共用同一次重折叠，
  额外成本仅为每个 group 两次 `push_back`；它仍是 ML 估计失败时 `fit_cfo()`
  兜底路径的信息来源（本次夹具中 `P4A_ML_FAILED_STAGE2=0`，但该路径必须保留）。

## 7. 未覆盖项与风险

1. **P3-A 删除 TM-1 / Whole-SYNC 探测**：理论上存在“coarse scan 与 fold 均未命中、但网格探测能命中”
   的窗口，此类窗口现在会失败。本批夹具（含 `-10/-12/-14 dB` heavy 网格与 SIC 24 组碰撞单测）未观察到退化。
2. **P2-B / P2-C 的“未观测依赖”**：审计覆盖 8 个实采文件与全部 payload QA；不构成
   对未采信道的保证。若后续出现低 SNR 丢包，优先用 `OPENUWB_AUDIT_ATTEMPT3` 的思路复核。
3. **P3-B 的宽扫删除**：本批夹具 `LockedBounded` 失败数为 0，收益仅由合成纯噪声单测覆盖。
4. **回放噪声**：见 §1.2；`jam884`/`jam688` 的绝对 FCS 不适合逐轮比较，`near348` 偶发 `raw_drop_samples>0`。
5. **未上板、未做 MATLAB 逐样点交叉验证、未验证 65/32、TWR/ToA、Radar 算法链路**。
6. 新增 `PayloadSubTimers` 两个只读计数字段：只影响 src 级消费者重编译，不进入 stdout/benchmark
   schema；若不需要可删除字段与两条计数断言（不影响生产行为）。
